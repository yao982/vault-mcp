# 公开科研检索评测集 v1

本目录提供 **10 篇真实英文论文、63 个 PDF 物理页、50 条中文问题**。其中 40 条问题有页级原文证据，10 条问题在固定语料中没有充分答案。40 条有答案问题全部属于中文问题检索英文论文；它们不是自动从标题改写的文件定位题，而是涉及方法选择、接口约束、实验设置和适用边界。

这是面向科研工具论文的小型回归集，不代表所有科研领域，也不是盲测榜单。问题由项目借助 AI 编写并逐条核对原文，尚未经过独立双人标注或专家裁决。现有公开论文可能已出现在模型训练数据中；不能据此宣称模型具备未见领域的泛化能力。

## 来源、许可与目录

全部 PDF 来自 JMLR 官方站点。**每篇 PDF 的物理第 1 页都明确写有 `License: CC-BY 4.0`**，并非依据 arXiv 默认许可推断。PDF 保持下载时原样，论文许可与文中软件的 MIT/BSD/AGPL 等许可证是两回事。作者姓名、原始论文链接、许可链接和署名要求保留在 [ATTRIBUTION.md](./corpus/ATTRIBUTION.md)。

| 文件 | 用途 |
| :--- | :--- |
| [corpus/manifest.json](./corpus/manifest.json) | 固定 PDF 路径、标题、官方 URL、论文许可证、语言和 SHA-256 |
| `corpus/papers/*.pdf` | 10 份未修改的官方论文，共 3,248,637 字节 |
| [corpus/license-evidence.json](./corpus/license-evidence.json) | 每篇首页许可短摘录、物理页数、字节数、作者与发表年份 |
| [questions.json](./questions.json) | 固定问题、dev/test 划分、可回答性和页级证据 |

| [corpus/no-answer-audit.json](./corpus/no-answer-audit.json) | 无答案问题的范围说明、逐题理由和全文术语核查 |
| [fetch-corpus.mjs](./fetch-corpus.mjs) | 缺失 PDF 下载及离线完整性/证据验证 |

| 划分 | 论文 | 有答案问题 |
| :--- | :--- | :--- |
| dev | GPflow；imbalanced-learn；scikit-multiflow；Pyro；giotto-tda | 每篇 4 题，共 20 题 |
| test | River；tslearn；Stable-Baselines3；GluonTS；mvlearn | 每篇 4 题，共 20 题 |

每个划分另有 5 条无答案问题，共 25 题。论文不跨划分。流式学习、时间序列、概率建模和兼容 scikit-learn 的库之间存在相近术语，可以作为同主题干扰资料。所有检索模式使用相同的十篇正文语料；dev/test 区分的是允许调参的问题及其对应论文，不是分别把另五篇论文从检索库删除。

**只把 manifest 中列出的 PDF 正文加入评测索引。不要索引本 README、问题、证据、许可说明或评测结果文件。** 否则可能把标准答案泄漏进检索语料。该集合没有导入个人知识库，也没有将合成文档伪装成真实论文。

## 冻结与核验

题库在任何检索质量运行之前冻结，时间为 `2026-09-25T14:07:42Z`。

```text
questions.json SHA-256
c1487c5be9de9dad887fa735aaba40336dd3e77abd22e0a88b914d45cdf50d91
```

不要为提高命中率修改问题、金标准页码或摘录。若发现事实标注错误，应发布新版本和勘误，保留原版校验和；不能静默改写冻结文件。调参只能使用 dev；test 用于配置冻结后的报告。如果观察 test 结果后再改实现参数，它便不再是未使用过的留出集，应公开这一点。

在仓库根目录安装项目依赖后执行：

```bash
# 完全离线：校验已有文件、首页许可、40 条页内证据及分组隔离
node benchmarks/fetch-corpus.mjs --verify

# 只下载缺失的官方 PDF，随后执行相同核验
node benchmarks/fetch-corpus.mjs

# 如需代理，可显式提供代理 URL；此可选模式需要 curl
node benchmarks/fetch-corpus.mjs --proxy http://YOUR_PROXY_HOST:PORT
```

已存在文件的 hash 不一致时脚本报错，不自动覆盖。官方 PDF 发生变化也会拒绝接收，以免悄悄改变评测语料。默认下载使用 Node.js 内置 `fetch`；不在代码中保存本机代理地址或凭据。

`--verify` 已验证 10 份文件的 SHA-256、10 条首页许可声明、50 条问题数量与分组、40 条证据的页内匹配以及论文不跨 dev/test。抽取中可能出现 PDF.js 的字体诊断；本次一个 `TT: undefined function: 32` 提示未阻止页面文字及证据核验。验证脚本的通过只证明数据完整性和文字出处，**不证明检索质量已经通过**。

## 页级与片段级证据如何计分

`evidence.page` 是 **1 起始的 PDF 物理页序**，不是 PDF 文档标签、印刷页码或解析后的 Markdown 行号。`evidence.quote` 直接取自该页文字，只折叠空白，不做翻译、模糊匹配、自动补词或自动去断行连字符。部分原文包含 `con- trib` 等排版断词，保留它们是为了可核验。全文页面已用 PDF.js 6.3.289 抽取核对。

建议分别报告，而不是混用一个“命中率”：

- **文件命中**：找对论文，作为最宽松的辅助指标。
- **页命中**：候选同时满足金标准文件与物理页；用于 Page Recall@k / Page MRR@k。
- **证据片段命中**：候选实际包含相应证据文字；比只命中整页更严格。引用因分块边界而分散时，应明确计分规则，不能事后拼接金标准冒充原始候选。

这些标注给出已核实的足够证据位置，不声称穷尽所有可接受的等价证据。若系统返回其他确能支持答案的段落，应独立裁决并在未来版本补充，而不是为了当前结果临时改标签。

论文描述的是其发表时的软件与实验，不是对应库的最新版本说明。查询中某些细节问题就是为了检测模型是否把今天的软件知识替代成论文证据。

## 无答案问题和公平对照

10 条无答案问题包括未报告的硬件测试、数据划分、能耗、置信区间和实验配置。它们通常与已收录论文主题相关，不能仅靠主题识别拒答。全文术语搜索只是辅助；例如 `90%` 在 tslearn 中是代码覆盖率，不能回答 GluonTS 预测区间覆盖率问题。

`answerable:false` 的含义是：**这十份固定 PDF 没有提供所请求的充分依据**，不是“互联网上不存在答案”。这类问题的 `evidence` 为 `[]`，`crossLanguage` 为 `false`，避免把没有正确英文证据的负例计入跨语言正例数量。

最低对照应包含相同语料、相同问题和相同 k 下的 BM25、向量、混合检索。记录模型 ID/版本、分块设置、抽取器版本、索引版本、硬件、缓存条件及耗时。若评估其他项目，公开原始命令、失败和资源占用，不为不同系统偷偷提供不同的翻译或查询扩展；需要额外预处理时，应单列实验条件。

无答案问题即使返回候选也不自动代表系统已声称有答案。应区分“检索仍返回 top-k”、“系统宣称找到了支持证据”和“生成回答出现无依据结论”。未实现可靠拒答时如实报告，不用任意分数阈值制造好看的拒答准确率。这里不提供调参后的最低命中率保证，也不预设混合检索一定优于其他基线。
