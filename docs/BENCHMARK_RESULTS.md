# v0.3.0-preview.1：实测、边界与未完成的验收

**当前结论：可以作为公开预览版试用，尚未达到正式版的全部门槛。** 真实用户试用和独立人工相关性审阅仍待完成。下列数字只描述固定语料和这次运行条件，不代表通用准确率。

## 数据与计分

10 篇 JMLR 英文软件论文，63 个 PDF 物理页，74 个实际索引切片。全部逐篇核实 CC BY 4.0；[原始文件、许可与复现](../benchmarks/README.md)。50 个中文问题在跑分前冻结：40 个有答案（全部中文查英文），10 个无充分答案；按论文划分 dev/test，各 20 个正例和 5 个负例。

题库 SHA-256：`c1487c5be9de9dad887fa735aaba40336dd3e77abd22e0a88b914d45cdf50d91`。只有论文正文进入评分索引，问题、答案说明、许可说明、个人资料和演示笔记均不进入。

命中要求：前 5 条候选之一同时满足正确文件、正确物理页、包含标注原文段落（仅折叠空白）。不是只找到论文标题。40/40 标注段落都能在对应页找到；两套模型运行各检查 703 条 PDF 候选，内容均能回到所标页核对，0 个定位错误。这只核验这些页面的文字和坐标，不保证任意表格、公式或多栏版式提取正确。

## 检索结果

| 配置 | dev 证据命中@5 | test 证据命中@5 | test MRR@5 |
|---|---:|---:|---:|
| 关键词 BM25 | 12/20，60% | 17/20，85% | 0.600 |
| BGE 中文向量 | 8/20，40% | 7/20，35% | 0.198 |
| BGE 混合 | 14/20，70% | 19/20，95% | 0.649 |
| E5 多语言向量 | 15/20，75% | 17/20，85% | 0.562 |
| E5 混合（新库默认） | 16/20，80% | 19/20，95% | 0.642 |

原始逐题候选：[E5](../benchmarks/results/multilingual-e5-small.json)、[BGE](../benchmarks/results/bge-small-zh.json)。所有正例都是跨语言问题，因此上述正例结果同时也是这份数据的跨语言结果。部分中文问题含 GPflow、tslearn 等英文库名/标识符，词法检索可以利用它们；**85% 的关键词结果不意味着关键词模型能够翻译中文。**

E5 在这份语料的纯向量模式明显好于 BGE，但两者混合模式的 test 命中数相同，不能据此宣称 E5 在所有模式均更好。MRR 衡量正确证据排得多靠前，也不等于回答正确率。20 个 test 正例规模很小，需要其他领域和独立标注补充。

**实现修复记录：** 第一次运行暴露 RRF 使用“文件路径 + 行号”合并 PDF 候选，导致不同页相同行号被错误合并；当时 E5 test 混合为 3/20。已用独立多页回归测试确认并改用 `citationId`，未修改题目、金标准、模型或排名参数。[首次无效运行](../benchmarks/results/initial-invalid-rrf.json)保留供审计。test 在修复前已经被观察，因此修复后的运行应视为固定留出回归，不能冒称严格一次性盲测。

## 成功与失败

- E5 混合 test 19 题的候选包含标注证据，但 T18“不同视图的特征维数是否必须相同”未命中，返回了同论文的其他页及相近主题。文件相关不等于证据充分。
- dev 的 D01（非共轭与规模）、D09（预序评估顺序）、D15（guide 对应关系）、D17（监督目标重对齐）也失败，说明还会漏掉具体方法约束和段落。
- 10 个无答案问题保存了所有实际候选，并标为 `pending-independent-human-review`。尚无独立人工相关性结果；不把返回候选算作有答案，不把警告文字或空结果算作可靠拒答。

## QMD 对照

独立安装固定的 `@tobilu/qmd@2.8.3`，独立配置/缓存/索引，不修改既有用户 QMD 数据。通过项目相同的 PDF.js 提取器导出每个物理页为一个 Markdown，再调用 QMD。没有手工翻译查询或增加答案上下文。

完整对照结果在本轮运行结束后补入。已有部分 vsearch 运行只包含 9 个 dev 正例，不能当作完整 test 成绩。QMD 2.8.3 的 vsearch 默认还包含 vec/HyDE 查询扩展，不是纯向量基线；query 还会进行混合检索与重排序。

比较边界：QMD 返回全文页，Vault 返回切片，上下文预算并不完全一致；相同“页 + 原文”约束有助于核对出处，但不足以隔离纯排序算法差异。QMD 命令行耗时包含进程/模型启动，首次还可能下载模型；不能与下表的预热进程内查询延迟直接比较。[QMD 环境与命令](../benchmarks/results/qmd-environment.json)。

## 模型、硬件与耗时

Windows 10.0.26200 x64，Node.js v24.15.0，Intel Core i9-14900HX（32 逻辑处理器），约 16.9 GB RAM。Vault 使用 Transformers.js 2.17.2 + ONNX Runtime CPU，PDF.js 6.3.289。两个配置都使用量化模型并归一化：

| 配置 | 模型 | 维度 / 池化 | 前缀 | 本次模型文件大小 |
|---|---|---|---|---:|
| BGE | Xenova/bge-small-zh-v1.5 | 512 / CLS | 无 | 24,451,050 B |
| E5 | Xenova/multilingual-e5-small | 384 / mean | query: / passage: | 135,392,016 B |

长输入计入特殊 token 与前缀，每窗最多 512 token，再按正文 token 权重聚合。混合使用 RRF，k=60，每分支先取 10 个候选，再返回 5 个。论文索引实测 BGE 约 3.19 秒、E5 约 6.27 秒；预热模型加载约 85 / 496 ms。下载不计入这些时间。本机 E5 首次下载与加载约 8.8 秒，仅为当时网络观察，不是安装承诺。

## 1,000 / 10,000 切片负载

使用带编号的合成英文科研短句，每文件一个切片，**全部真实调用 E5 并持久化向量，没有使用 mock 或随机向量**。这些数据只测吞吐，不是质量证据。1k 首次索引 26.531 秒；新增 9k 的第二轮 410.381 秒（同时跳过原 1k），累计 10k 索引 436.912 秒。文件生成和模型加载单列，不计入索引时间。

各模式、各规模预热后 50 次；下表包括查询向量生成和返回来源版本检查：

| 切片 | BM25 P50 / P95 | 向量 P50 / P95 | 混合 P50 / P95 |
|---:|---:|---:|---:|
| 1,000 | 8.670 / 12.991 ms | 26.953 / 42.501 ms | 31.209 / 44.795 ms |
| 10,000 | 25.084 / 28.955 ms | 133.308 / 177.741 ms | 139.150 / 182.826 ms |

10k 时纯数据库混合检索 P50/P95 为 101.500/144.546 ms；单独查询向量为 6.053/13.293 ms。不同采样阶段的分位数不能直接相加。进程 high-water RSS 为 **1,224,892,416 B（约 1.14 GiB）**；50 ms 定时采样只捕捉到约 558 MiB，同步负载会阻塞采样，因此峰值以内核报告的 `maxRSS` 为准。[完整性能原始记录](../benchmarks/results/performance.json)。

QMD 负载在这轮性能测量期间暂停，避免两个模型竞争。这里测的是本机预热进程内范围，不是服务并发性能、任意长度论文切片或其他硬件的延迟保证。当前向量检索仍全量扫描，10k 索引耗时也说明大库体验还有优化空间。

## 工程验证与发布门槛

本机已经实际验证独立 npm 压缩包安装后的入口、index/search/read/status，并检查包内没有数据库、锁或缓存。真实缓存模型集成 4/4 通过，覆盖两种模型、构建后的 MCP 和旧检索回归。完整回归及跨平台结果以 [CI](https://github.com/yao982/vault-mcp/actions/workflows/ci.yml) 的最终记录为准。

正式版还需：跨平台矩阵完成；独立复核评测；首批 5 名真实用户中至少 4 名依据文档独立安装并完成首次有效检索。当前真实试用人数为 0，不以自动测试替代。[公开征集与反馈模板](TRYOUT.md)。
